# Capstone traffic and evidence matrix

This matrix describes the default address plan and intended paths. **Every Azure runtime result is unverified.** Resource assertions and synthetic response fixtures establish configuration and verifier behavior only. No live traffic, deployment or recovery pass is part of the overhaul release gate.

Use `terraform output -json` to obtain configured targets after a learner chooses to deploy. In particular, use `private_endpoint_ips` for exact Blob/Key Vault addresses: an arbitrary RFC1918 response is insufficient. `FW` means the actual Firewall private IP output; `IN` is the resolver inbound IP (`10.0.1.4` for the default plan); `CORP` is `192.168.1.4`. Service names are generated from the deployed account/vault outputs, never guessed from a naming prefix.

The resolver outbound-to-corporate DNS path uses VPN routing directly. No Firewall DNS network rule is presented as evidence for a path that does not cross Firewall. Conversely, private endpoint HTTPS inspection relies on application rules and their return-path behavior; substituting a network rule is a design change requiring review.

## Diagnosing a mismatch

Keep DNS answer, route selection, NSG/Firewall decision, TCP/HTTP result and identity authorization as separate evidence. A 200 response without route/log evidence does not prove inspection. A VPN Connected status does not prove bidirectional DNS or application reachability. A 403 can come from WAF, network policy or data authorization; record the responding service and test context.

The fixture verifier reports missing observations as SKIP and mismatches as FAIL. Fixture PASS means that supplied synthetic evidence matches the expected decision, not that Azure produced it. Deliberate route, DNS and policy failures are authored exercises for learners; this overhaul validates their instructions and response interpretation locally.
